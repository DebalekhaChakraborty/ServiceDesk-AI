# Restart Windows Update Service (wuauserv)

**KB ID:** 1025-WUAUSERV-RESTART  
**Title:** Restart Windows Update Service (wuauserv)  
**Affected Service:** Windows Server / Workstation Update Agent  
**Category:** Infrastructure → Operating System  
**Last Updated:** 2025-11-09

---

## 🧠 Problem Description

Windows Update can hang or become unresponsive, causing patching to stall or never start.

### Common Symptoms
- Windows Update stuck on “Checking for updates…”
- Pending updates never install
- Update scans do not trigger
- Event logs reference **wuauserv**

**Keywords:** `windows`, `update`, `wuauserv`, `patching`, `wuauclt`

---

## 🧩 Root Cause

The **Windows Update Service (wuauserv)** is stopped, hung, or in a bad state (often after long patch cycles or cache issues).

---

## 🧰 Manual Resolution (Reference for Admins)

1. Open **Command Prompt** as Administrator.  
2. Stop the Windows Update Service:  
   ```cmd
   net stop wuauserv
   ```
3. Start the Windows Update Service:  
   ```cmd
   net start wuauserv
   ```
4. Confirm the service is running:  
   ```cmd
   sc query wuauserv
   ```
   Expect `STATE : 4  RUNNING`.
5. Trigger a fresh update detection:  
   ```cmd
   wuauclt /detectnow
   ```
   On Windows 10/11 and Server 2016+, use:  
   ```cmd
   UsoClient StartScan
   ```

If the scan still does not progress, the update cache is likely corrupt. This is
a **manual** escalation step and is deliberately not automated:

```cmd
net stop wuauserv
ren %windir%\SoftwareDistribution SoftwareDistribution.old
net start wuauserv
```

Windows rebuilds `SoftwareDistribution` on the next scan. If the problem
persists after a cache rebuild, escalate to **L2-Windows** rather than repeating
the restart.

## 🤖 Automation Notes (System Context)

- The agent maps this request to the approved action `win.restart_wuauserv`.
- `target_host` comes only from its trusted target-class source. The agent must
  never ask the user to type a hostname or IP, and must never infer one from the
  conversation.
- Preconditions are checked once via the policy layer before execution:
  `host_is_authorized`, `endpoint_reachable`, `endpoint_is_windows`.
- Execution is a single remote `Restart-Service -Name wuauserv -Force` over
  WinRM — not a separate `net stop` followed by `net start`. The manual steps
  above are the admin equivalent, not the commands the automation issues.
- The action returns `exec.status` and `exec.message`. Its only declared effect
  is `windows_update_service_restarted(<target_host>)`.
- Automation restarts the service **only**. It does not rename or delete
  `SoftwareDistribution`, does not install or approve updates, and does not
  reboot the host.
- On failure the agent offers the existing ServiceNow incident path with the
  captured error output. It does not retry the restart in a loop.
